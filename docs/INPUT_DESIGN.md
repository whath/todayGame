# 本地双人输入

## 槽位与输入源

P1/P2 是两个稳定 PlayerInputSlot，Keyboard A/B 是同一物理键盘上的两个逻辑设备。每次手柄连接对应一个独立 GamepadInputDevice。

第一个未绑定设备的加入事件分配给 P1，第二个分配给 P2。InputManager 检查 deviceId，已绑定设备不会再次加入；绑定分配统一从管理器发生。

支持的组合是两套键盘、键盘与手柄（任意加入顺序）、两只手柄。两把 USB 键盘通过 Cocos 汇总成键盘事件，不声称可按硬件身份区分。

## 逻辑动作

| 动作 | Keyboard A | Keyboard B | 手柄 |
| --- | --- | --- | --- |
| Move | WASD | 方向键 | 左摇杆 / 十字键 |
| Primary | F | J | South |
| Secondary | G | K | East |
| Interact | E | L | West |
| Join | 任一映射键 | 任一映射键 | 面键、肩键、扳机、摇杆按下、菜单 / Start / Share、十字键 |

默认按键由 SettingsRegistry 注册，通过设置页分别修改 P1/P2。Keyboard A/B 在加入前使用各自默认配置，加入后按拥有的玩家槽位读取配置；映射变更需要松开全部按键才能继续，避免同一按住事件重复加入。

`Esc` 暂停 / 继续，`F2` 打开设置，`F5` 重置角色位置，`F1` 开发诊断。这些全局命令不交给 Player。菜单使用方向键 / Enter / Tab / Esc；手柄通过菜单键打开设置，方向输入 / South / East / R1 导航。系统 Home 等保留按钮不属于加入按钮。

Move 长度不超过 1，防止键盘斜向加速。摇杆默认径向 0.2 死区，可按 P1/P2 在 0.05–0.5 内调整，并重映射 0–1 保留模拟力度；十字键优先。按钮输出按下沿，按住不会连续触发动作。重绑定支持跨玩家冲突检测、交换、解除原绑定和取消，不修改设备 ownership。

KeyboardAdapter 保存本帧按键脉冲，即便快速按下并松开，Join 仍可被识别。动作采样是逐帧状态：极短于一帧的动作点按仍需后续实机确认，当前不提供动作事件队列。

## 加入与掉线

1. 主菜单选择新游戏 / 继续后进入加入页，两个槽位初始 WAITING。
2. 两个设备完成加入后选择“开始”；应用进入 gameplay 并创建两个角色，设备会话为 PLAYING。
3. 任一手柄断开后保持原槽位及角色位置，双方暂停，界面显示 DISCONNECTED。
4. 手柄重新连接产生新的连接标识；按按钮确认，或用空闲键盘映射接管。
5. 先恢复断开槽位，再填充空槽位；两个槽位断开时按 P1、P2 顺序恢复。
6. 全部恢复后自动继续；另一玩家已绑定设备不能被抢走。

不凭数字 deviceId 推断重连手柄的物理身份；该编号可能被引擎 / 系统复用。恢复流程依赖用户按键确认的顺序，不承诺跨重连永久识别硬件序列号。

设置页“返回加入界面”经确认后释放槽位并重置位置；`F5` 重开当前关卡，重置机关和游戏计时。返回后需要松开旧按键再加入。主菜单、设置和手动暂停期间继续采样但禁止 Join；加入页允许 Join，游戏中允许断线接管。菜单语义与玩家语义独立，加入页的方向输入也可参与加入。

## 平台与待验证项

使用 Cocos `GAMEPAD_CHANGE` / `GAMEPAD_INPUT`，从 EventGamepad 读取手柄，不在玩法层调用 navigator 或 Windows API。已连接手柄可以通过第一次输入事件被发现。引擎到手柄驱动之间的兼容性、双手柄枚举、失焦状态与热插拔均未实际验证。

浏览器预览需要页面焦点，部分环境需要先按手柄按钮才暴露设备。Windows 原生版应单独验收，不能用网页预览结果替代。双键盘多键同时输入还受键盘硬件防冲突能力影响。
