# Prototype Gate → Direction Lock → Vertical Slice

当前状态：NOT RUN。玩家试玩和游戏运行按用户要求暂缓；自动测试不能替代乐趣、沟通或市场验证。接力关暂为候选 A，尚未达到 10–20 分钟原型范围。

## Gate 记录模板

每个候选记录：玩法假设、双人相互影响方式、目标体验时长、Build ID、设备组合、测试日期、参与者对数、玩法版本、卡点、提示次数、等待片段、完成／失败／再试情况、可分享事件、录制片段时间戳。无录像时 Footage Markers 填 NOT RECORDED。

现场观察问题：是否主动交流、互相帮助；是否产生有趣影响和失误；失败是否有趣；是否有紧张或笑点；是否有玩家长时间无事可做；规则能否理解；是否主动再玩；是否存在值得讨论或剪辑的瞬间。

结果只允许 KEEP / ITERATE / KILL，当前留空。每个判断附具体观察证据，样本少时不宣称市场需求已验证。ITERATE 先改玩法、提示或布局；KILL 删除或隔离实验，不继续加 Framework 掩盖问题。

## Direction Lock

依据 A / B / C 候选的实际观察，写清核心循环、目标玩家、合作价值、首发平台、内容规模及明确不做项。候选数量是比较工具，不要求先制作三套完整游戏。不把现有设施主题、接力机关或解谜类型当成永久产品方向。

## Pack 准入卡

填写 Pack 名称、哪项当前机制需要、为什么现有原语不足、最小内容范围、验收条件、接入的真实关卡／原型、删除条件。四项门槛缺任一项都不开发。Combat、Puzzle / Physics、Narrative、Mission、Roguelike、Management、Social / Chaos 按需要选择；不一次性创建。

## Vertical Slice Gate

必须验证：启动 → 主菜单 → 双人加入 → 关卡 → 核心合作 → 成功／失败 → 保存 → 结算 → 返回菜单。启用的 Pack 必须覆盖真实流程，且完成 Windows 与控制器 Gate、存档恢复、资源生命周期和目标品质的表现。

全部证据通过后才 Foundation Lock，转向正式内容生产。之前不能承诺只补 UI／故事即可上线；之后仅因 Slice 或生产中的具体问题重新打开对应基础模块。
