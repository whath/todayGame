# 协作实验 01：守门与接力

## 数据与规则

内容 ID 为 `level.coop.relay_01`。CoopLevel 定义踏板、闸门、终端、交互半径、出口和静态墙体；原 `level.prototype.room_01` 不改 ID 或布局，供 Labs 与旧存档继续使用。新游戏默认选择接力关。

CoopChallenge 是不依赖引擎的规则类。站在踏板区域中的玩家提供电源；另一玩家在终端半径内按槽位的 interact 上升沿，使 gateLatched 永久为 true。只有永久解锁后两人都在出口，completed 才变为 true。没有角色固定职业或单独控制器。

每帧在移动前计算门的碰撞状态，再用同一 CollisionWorld 移动两人，移动后解析交互与成功。门口有角色 AABB 时保持开启，防止关门造成重叠；角色离开门口且踏板无人时重新关闭。暂停、断线、菜单及切换期间不推进机关交互；通关后停止移动和游戏时间，保留结果菜单。

CoopPresentation 只画标签、机关区域和状态；PrototypeHUD 显示当前目标、P1/P2 的角色提示及实际交互绑定。物理按键仍只存在于平台层。没有引入刚体、网络或通用机关编辑器。

## 存档与重试

schema 3 在 Session 中增加 coop 的 gateLatched / completed。旧 schema 1 经 2 迁移到 3；schema 2 测试房间保持原关卡 ID、位置、seed 和时间。旧程序遇到 schema 3 将执行已有未来版本保护。

终端解锁后保存一个检查点，双人通关后记录 completedLevelIds 并保存，手动保存和退出保存继续有效。读取时验证机关布尔值、关卡对应关系及通关必须永久开门且两人位于出口。站在门口的存档恢复后先计算防夹状态，再允许移动。

F5、暂停菜单重开和通关界面再试都会重新创建关卡，清空本次机关状态和计时，保留 Profile 已完成记录。重开本身不覆盖磁盘检查点；再次保存、解锁或通关后写入新状态。保存失败时暂停显示错误，当前机关状态仍保留供重试保存。

## 验证和范围

自动测试使用同一规则与碰撞类，从出生点逐步移动并完成整个解锁／撤离流程，分别交换 P1/P2 分工；另覆盖未供电、距离不足、门关闭阻挡、门口保护、暂停不交互、双方出口、状态读写、旧档迁移和重开。

这是无头逻辑验证，没有启动 Cocos 游戏或验证屏幕表现。玩法是否易懂、镜头和字号是否合适、手柄操作是否顺畅，仍需后续试玩。
