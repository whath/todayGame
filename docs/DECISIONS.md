# 技术决策

## 2026-09-22 — v0.2 核心服务与设置扩展

新版规划将设置和核心服务插入玩法实验之前。按用户新指令推进 v0.2 开发并执行自动验证；上一轮“本次不校验”不扩展为永久禁测。原 v0.1 实机 Gate 不伪装通过，版本维持 dev，不创建发布 Tag。

设置事务、校验、迁移与纯服务不依赖 cc；Cocos 代码留在平台和组装层。实际支持的能力才开放：原生显示、Gamma、VSync、震动与字幕暂时隐藏。高风险确认流程先实现并测试框架，不用无效菜单假装原生能力已完成。

P1/P2 设置跟随玩家槽位，因此键盘 B 先加入时会切换到 P1 配置。切换期间等到物理键全部松开，避免同一按住事件被另一映射当作 Join。对应事件桥接回归测试已加入。

开发依赖增加 TypeScript 5.9.3 与官方 @cocos/creator-types 3.8.6，用于可重复的无头类型检查和 Node 测试；无新增生产依赖。仅为官方类型包缺失的 cc/env DEBUG 提供测试用声明，不模拟引擎 API 来绕过类型检查。

Esc 改为暂停，F2 设置，F5 重置；返回加入界面移至设置页确认操作。音频与失焦暂停独立。无需进度存档、复杂 SceneFlow 或完整 Agent/Skill 平台时不提前实现。

## 2026-09-22 — 第一批源码与正式发布分开

用户要求基于总规划生成第一版基础代码并上传，同时明确不校验、不执行。此次覆盖基础功能代码和工程文档，跳过所有运行验证，保留 `0.1.0-dev`，不创建 `v0.1.0` Tag。规划中的 Task 0 示例指令是资料，不限制当前请求只能生成文档。

## 2026-09-22 — 固定 Cocos Creator 3.8.6

在规划的 3.8.x 范围内选择具体补丁版，便于资源格式、原生输入和后续构建对齐。由 Creator 生成引擎声明与缓存，不通过 npm 引入另一套 cc 包。

## 2026-09-22 — 先做俯视矩形房间

没有题材和美术要求，使用 XY 平面和几何占位，便于观察独立移动、边界和双人视野。此选择不决定后续游戏类型。

## 2026-09-22 — 静态运动学碰撞

当前仅需要方形角色与静态矩形阻挡，使用小型轴向扫掠 CollisionWorld，避免引入重力、刚体、后端选择及序列化物理配置。限制是无动态物理、旋转或角色互相阻挡。出现推箱子等需求后优先切换引擎 Physics2D。

## 2026-09-22 — 热插拔需要重新确认

设备数字编号不等于永久硬件身份。每次连接生成新标识，断开玩家保持槽位，按键明确恢复，防止自动把复用编号分配给错误玩家。两个玩家同时掉线时按 P1、P2 顺序确认。

## 2026-09-22 — Prefab 与运行时装配

保留一个真实 Player.prefab，由入口实例化两次。房间 / HUD 用运行时 Graphics 与 Label 构造，减少首版占位资源，同时保留可编辑场景和元数据引用。后续正式 UI 或关卡可以替换装配模块。

## 2026-09-22 — 暂不搭建完整 Agent / Skill 平台

本次用户要的是游戏基础代码。落实简短 AGENTS.md、架构与任务模板即可；不把总规划中所有专业角色、技能目录和未来平台一次性变成工程依赖。

## 2026-09-23 — v0.3 Runtime & Content Foundation

按 v3 的 R0–R12 范围继续现有工程，保持 Cocos 3.8.6，无新增生产依赖。R0 审视与设计见 RUNTIME_DESIGN。应用状态独立于双人设备状态；当前只需一个正式场景容器，选择逻辑视图适配器和显式资产作用域，不强行拆多个物理场景或 Bundle。

存档 DTO 与引擎对象、设置独立，schema 2 支持 schema 1 迁移。localStorage 用临时 / 提交 / 备份记录和回读实现恢复能力，不宣传断电原子写入。备份保留迁移前原始内容。实验场景存档隔离，设备身份不进入 Session。

四个 Lab 对应 R10，构建准备工具给 Playtest / Release 明确场景白名单并关闭开发入口。较早规划提到的 AudioLab 因暂无真实音频素材暂不单建。没有实现对象池、复杂玩法标签、Stats、Replay、Networking、Mod SDK 或任意脚本控制台。

自动验证不等于引擎运行：Windows Build、真实控制器导航、资源导入和 UI 视觉仍为 NOT RUN，因此保持 0.3.0-dev，不创建版本 Tag。


## 本轮 — 先验证合作机关

首个互动选择踏板临时开门、另一位队友操作终端永久解锁、双方撤离，不引入战斗、搬运物理和通用交互框架。门中有人时保持开启避免夹住；两人角色能力相同，分工由玩家决定。规则是纯逻辑，表现独立；新关卡使用新稳定 ID，旧布局不改。

Session schema 升到 3，避免旧程序静默忽略新机关状态；v1/v2 档保留旧房间并迁移，原始备份不变。用户明确暂不运行游戏，因此仅做无头代码验证，不安装 Creator、不执行预览或构建，不创建发布 Tag。

新版为路线重写，不删除已有 v0.1–v0.3 能力。补齐 Co-op Robustness 与最小 Gameplay Kernel，并在真实接力流程使用，保留关卡数据选择空间策略。主菜单 Any，模态与暂停按打开来源锁定；键鼠无法辨识人，作为共享来源，断线释放防止软锁。队友关系／动作／Trigger 不加入 Health、Damage 或 Quest。
